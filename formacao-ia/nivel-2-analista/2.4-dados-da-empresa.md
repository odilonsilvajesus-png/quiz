# Módulo 2.4: Dados da empresa

**Nível:** 2, Analista
**Pré-requisitos:** Módulos 2.1 a 2.3
**Esforço estimado:** 12 a 15 horas

---

## Objetivos de aprendizagem

1. Inventariar os dados de uma empresa: onde estão, em que formato, quem é o dono.
2. Avaliar a qualidade dos dados com critérios objetivos.
3. Diferenciar dados estruturados, semiestruturados e não estruturados, e o que cada um permite em IA.
4. Determinar a **prontidão de dados** para cada oportunidade.
5. Planejar ações de organização e limpeza de dados.
6. Capturar o **conhecimento tácito** (que está na cabeça das pessoas).

---

## Aula 1: Por que dados decidem o sucesso

> "Lixo entra, lixo sai."

A IA generativa reduziu muito a necessidade de dados históricos para treinar modelos, porque os modelos já vêm treinados. Mas ela **não** eliminou a dependência de dados:
- Um assistente de produtos com **catálogo errado** responde errado.
- Um bot de atendimento sem acesso ao **estoque real** inventa ou não ajuda.
- Uma análise de vendas sobre uma **planilha inconsistente** gera conclusões falsas.
- Uma base de conhecimento com **políticas desatualizadas** cria problemas com clientes.

**Na prática, organizar os dados costuma ser de 30% a 60% do esforço** de um projeto de IA integrado. Quem não prevê isso estoura prazo e orçamento.

> 📌 **Em resumo**
> - A IA generativa reduziu a necessidade de dados para treinar, mas não a necessidade de dados corretos.
> - Organizar dados costuma ser de 30% a 60% do esforço de um projeto integrado.

## Aula 2: Tipos de dados

| Tipo | Descrição | Exemplos | Uso em IA |
|---|---|---|---|
| **Estruturado** | Tabelas com colunas definidas | ERP, planilhas organizadas, banco de dados | Consultas, análises, ferramentas de agentes, ML preditivo |
| **Semiestruturado** | Tem estrutura, mas flexível | XML da NF-e, JSON de APIs, e-mails (cabeçalho + corpo) | Extração direta, integrações |
| **Não estruturado** | Texto livre, imagem, áudio | Conversas de WhatsApp, PDFs, contratos, fotos, áudios, manuais | **Grande força da IA generativa**: extrair, resumir, classificar, RAG |
| **Tácito** | Conhecimento na cabeça das pessoas | Como a Célia sabe quando comprar; como o Antônio negocia | Precisa ser **capturado** antes (Aula 6) |

> **Insight para o cliente:** a maior parte da informação de uma PME é **não estruturada** (WhatsApp, e-mail, documentos) e até pouco tempo estava "perdida" para análise. A IA generativa transforma esse material em ativo.

> 📌 **Em resumo**
> - Dados estruturados, semiestruturados, não estruturados e tácitos pedem abordagens diferentes.
> - A maior parte da informação de uma PME é não estruturada, e a IA generativa a transforma em ativo.

## Aula 3: Inventário de dados

### Como fazer
Para cada fonte de dados identificada nas entrevistas e na observação, registre:

| Campo | Descrição |
|---|---|
| **Fonte** | Nome do sistema/arquivo/canal |
| **Conteúdo** | Que informação contém |
| **Tipo** | Estruturado / semi / não estruturado / tácito |
| **Formato** | Banco de dados, XLSX, CSV, PDF, imagem, áudio, papel |
| **Volume** | Quantidade de registros, tamanho, frequência de geração |
| **Localização** | Nuvem, servidor local, computador pessoal, celular, papel |
| **Acesso** | API? Exportação? Só manual? |
| **Dono** | Quem é responsável e quem atualiza |
| **Atualização** | Tempo real, diária, mensal, nunca |
| **Qualidade** | Nota de 1 a 5 (Aula 4) |
| **Sensibilidade** | Contém dados pessoais? Sensíveis? Financeiros? Segredo comercial? |
| **Oportunidades que dependem** | OP-01, OP-07... |

### Exemplo (Casa Aurora, parcial)
| Fonte | Conteúdo | Tipo | Formato | Acesso | Dono | Qualidade | Sensibilidade |
|---|---|---|---|---|---|---|---|
| ERP | Produtos, estoque, vendas, clientes | Estruturado | Banco local | Exporta CSV, sem API | TI terceirizada/Juliana | 3 | Dados pessoais de clientes |
| WhatsApp (2 celulares) | Conversas com clientes | Não estruturado | App | Exportação manual por conversa | Atendentes | 2 (dispersos) | Dados pessoais |
| Planilha de frete | Tabela de frete por bairro | Estruturado | XLSX | Arquivo | Logística | 4 | Baixa |
| Planilhas financeiras (40+) | Contas, metas, cotações | Estruturado (inconsistente) | XLSX com macros | Arquivos locais | Marcos | 2 | Financeiro |
| Caixa de e-mail | NF-e, boletos, fornecedores | Semi/não estruturado | Gmail | API do Gmail | Administrativo | 3 | Financeiro |
| Conhecimento de compras | Quando e quanto comprar, fornecedores | Tácito | Cabeça da Célia | Entrevista | Célia | — | Segredo comercial |

> 📌 **Em resumo**
> - Para cada fonte: conteúdo, tipo, formato, volume, localização, acesso, dono, atualização, qualidade e sensibilidade.
> - Ligue cada fonte às oportunidades que dependem dela.

## Aula 4: Qualidade de dados

### As 6 dimensões da qualidade
| Dimensão | Pergunta | Exemplo de problema |
|---|---|---|
| **Completude** | Os campos estão preenchidos? | 40% dos clientes sem telefone |
| **Precisão** | Os valores estão corretos? | Estoque do sistema difere do físico |
| **Consistência** | O mesmo dado é igual em todos os lugares? | Preço diferente no ERP e na planilha |
| **Padronização** | Segue um formato único? | "Cimento CP II", "CIMENTO CP-2", "cim cp2 50kg" |
| **Atualidade** | Está atualizado? | Tabela de preços de 6 meses atrás |
| **Unicidade** | Há duplicidades? | Mesmo cliente cadastrado 3 vezes |

### Escala de qualidade (1 a 5)
- **1:** inutilizável sem retrabalho total
- **2:** muitos problemas; uso arriscado
- **3:** utilizável com limpeza moderada
- **4:** bom; pequenos ajustes
- **5:** confiável e governado

### Como avaliar rapidamente
1. Peça uma **amostra** (100 a 500 registros, anonimizada se tiver dados pessoais).
2. Use IA para ajudar: carregue a planilha em um assistente com análise de dados e peça:
   > "Analise a qualidade desta base: percentual de campos vazios por coluna, valores duplicados, inconsistências de formato, valores fora do padrão. Dê exemplos de cada problema."
3. **Confira manualmente** uma parte do diagnóstico da IA.
4. Atribua a nota com justificativa.

> ⚠️ **LGPD:** para avaliar qualidade, raramente é preciso ver dados pessoais reais. Peça amostras anonimizadas ou mascaradas, e use ferramentas em planos que não usam dados para treinamento (Módulo 4.4).

> 📌 **Em resumo**
> - Seis dimensões: completude, precisão, consistência, padronização, atualidade e unicidade.
> - Avalie com amostras e apoio de IA, conferindo parte do resultado à mão.
> - Para avaliar qualidade, raramente é preciso ver dados pessoais reais.

**Para ir além**
- [Kaggle Learn](https://www.kaggle.com/learn): microcursos gratuitos de análise de dados.

## Aula 6: Capturando o conhecimento tácito

Muitas PMEs dependem de **pessoas-chave** que sabem coisas que não estão escritas em lugar nenhum. É um risco enorme (e se a pessoa sair?) e, ao mesmo tempo, uma ótima oportunidade de IA.

### Técnica de captura em 5 passos
1. **Entrevistas estruturadas** (gravadas e transcritas) com a pessoa-chave, focadas em decisões:
   - "Como você decide quando comprar o produto X?"
   - "Quais sinais te dizem que algo vai dar errado?"
   - "Quais são as exceções?"
   - "Me conte um caso em que você errou e o que aprendeu."
2. **Observação** da pessoa tomando decisões reais, pedindo que "pense em voz alta".
3. **Estruturação com IA:** a partir das transcrições, peça a um assistente para gerar:
   - regras e heurísticas ("se o estoque cai abaixo de X e é alta temporada, então...");
   - perguntas frequentes e respostas;
   - um passo a passo de procedimentos;
   - uma lista de exceções.
4. **Validação** com a própria pessoa ("está certo? falta algo?").
5. **Publicação** em uma base de conhecimento usável (documento, assistente, RAG).

### Benefícios para o cliente
- Reduz a dependência de pessoas-chave (objetivo estratégico em empresas familiares e em sucessão).
- Acelera o treinamento de novos funcionários.
- Vira base para assistentes e automações.

### Esquema da aula

```mermaid
flowchart LR
    A["Entrevistas focadas em decisões"] --> B["Observação pensando em voz alta"]
    B --> C["Estruturação com IA: regras, FAQ, passo a passo"]
    C --> D["Validação com a pessoa"]
    D --> E["Publicação: documento, assistente ou RAG"]
```

*Figura: os cinco passos da captura de conhecimento tácito.*

> 📌 **Em resumo**
> - Empresas dependem de pessoas-chave com conhecimento não escrito: é risco e oportunidade.
> - Entrevistas sobre decisões, observação, estruturação com IA, validação e publicação.
> - Resultado: menos dependência, treinamento mais rápido e base para assistentes.

## Aula 7: Plano de ação de dados

Para cada problema de dados que bloqueia oportunidades prioritárias, defina:

| Problema | Ação | Responsável | Esforço | Prazo | Destrava |
|---|---|---|---|---|---|
| Descrições de produtos sem padrão | Padronizar as 500 mais vendidas (com IA ajudando) | Rafael + você | Médio | 30 dias | OP-01, OP-02 |
| Sem acesso automatizado ao ERP | Avaliar exportação agendada ou conector | Você + TI | Médio-alto | 45 dias | OP-02 |
| Conhecimento de compras tácito | 5 sessões de captura com Célia | Você + Célia | Médio | 30 dias | OP-12 |
| Planilhas financeiras inconsistentes | Consolidar em modelo único | Marcos | Alto | 90 dias | Análises financeiras futuras |

### Princípios
- **Comece pelos dados que destravam os quick wins.** Não tente "arrumar todos os dados da empresa".
- **Use IA para limpar dados:** padronizar descrições, deduplicar cadastros, classificar registros. É, por si, um quick win.
- **Defina donos.** Dado sem dono volta a ficar ruim.
- **Crie rotinas de manutenção.** Quem atualiza, quando e como.

> 📌 **Em resumo**
> - Comece pelos dados que destravam os quick wins.
> - Use IA para padronizar, deduplicar e classificar: isso já é um quick win.
> - Dado sem dono volta a ficar ruim: defina responsáveis e rotinas.
